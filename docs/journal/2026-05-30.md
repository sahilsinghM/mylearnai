## Session 1: Office Hours — Proof Trail

### Problem reframed

Started with a 9-component learning platform vision. Narrowed to a single wedge: **proof trail**. Every Socratic session ends with a LinkedIn post draft + GitHub-ready project spec. No competitor produces proof — every existing tool (The Rundown, TLDR AI, 100.school, The Batch) optimizes for consumption metrics. The proof trail is the only unoccupied position.

### Target user

A mid-level software engineer, currently employed full-time, who:
- Wants a job at a frontier AI lab specifically (not just "learn AI")
- Can only consume content during work hours in 5–10 min bursts
- Builds in the evenings
- Has finished at least one structured AI course but feels stuck between "knows the theory" and "can prove it"

**This user is the founder.**

### Key insight

The doom loop: passive consumption → failed ChatGPT sessions → abandoned courses. The real pain is **sequencing**, not content. There's too much content; the problem is not knowing which thing to do first.

## Session 2: CEO Review — Proof Trail Plan

### Mode: SELECTIVE EXPANSION

Design doc was already approved, so review focused on: architecture gaps, error & rescue map, schema correctness, and optional cherry-picks.

### Key findings

**Architecture gap:** `close-session/route.ts` returns data but never writes to DB. The `tutor_sessions` table doesn't exist yet. The plan doc said `ALTER TABLE` but the table doesn't exist — it should be `CREATE TABLE`. Both fixed in the CEO plan.

**Session save decision:** Server-side insert in close-session (atomic with Claude response). Never trust the browser to persist critical state.

**Route structure fix:** `/api/proof/[id]` PATCH handler needs its own file (`[id]/route.ts`) — Next.js App Router doesn't support dynamic segments in the same route file as static handlers.

**Revalidation strategy:** `revalidatePath('/proof')` called server-side from the close-session route handler after successful insert.

### Schema (final)

```sql
CREATE TABLE tutor_sessions (
  id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id             uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  session_date        timestamptz NOT NULL DEFAULT now(),
  week_topic          text NOT NULL,
  gaps                jsonb NOT NULL DEFAULT '[]',
  project_title       text,
  project_desc        text,
  acceptance_criteria jsonb NOT NULL DEFAULT '[]',
  proof_line          text,
  github_url          text,
  linkedin_published  boolean NOT NULL DEFAULT false,
  created_at          timestamptz NOT NULL DEFAULT now(),
  updated_at          timestamptz NOT NULL DEFAULT now()
);
```

With RLS, indexes, and an `updated_at` trigger.
